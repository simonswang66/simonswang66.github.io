1

设计原则

本规范服务于 KPMG 审计技术解决方案（Audit Tech Solution）系列产品。下列 5 条原则是所有视觉与交互决策的顶层依据。
原则 01
审计业务优先

界面服务于审计业务流程，不为视觉美观牺牲信息密度。专业感与可用性优先于装饰性元素。

原则 02
风险可识别

异常、风险、警示状态用统一语义色（红/橙/绿）即时传达。风险等级可视化需贯穿列表、卡片、详情页。

原则 03
留痕可追溯

所有操作、变更、审批均有可追溯的视觉标记和时间戳。PBC 状态、底稿留痕、复核链是审计合规的核心。

原则 04
数据密度合理

高密度表格与摘要卡片共存，按场景切换。KPI 汇总区使用 4 列布局，详情表格使用紧凑型单元格。

原则 05
视觉克制

平台主蓝为交互核心，蓝绿粉橙区分资金与税票语义。卡片使用细边框、浅灰头部和左侧蓝条建立层级，不使用厚重装饰。

A.3 标准构成

本规范按组件使用场景分类组织，作为审计技术解决方案所有产品的共同设计基线：

  • 设计原则：审计业务优先、风险可识别、留痕可追溯、数据密度合理、视觉克制
  • 全局样式：色彩 token（含五档色阶）、字体与数字格式、页面布局
  • 通用：按钮、图标、标签与徽章、卡片与区块（含卡片内分区）
  • 导航：Tab、面包屑、进度与状态（四步流程 / 状态跟踪）
  • 数据录入：表单、搜索框、基础控件、筛选、上传与附件
  • 数据展示：表格体系（基线 / 常用单元格写法 / 排序筛选 / 冻结列 / 分组行 / 多级子表 / 单元格可视化）、统计图表、时间线
  • 反馈：弹窗、抽屉、消息提示、页面状态
  • 业务组件：按用途并入各章 —— 业务徽章（示例：PBC / 风险等级 / 调节平衡 / 对手方类型）见 3.3.2，业务卡片（示例：工作底稿卡 / 重要性水平指示器）见 3.4.3，多选下拉见 5.4.3，单元格可视化见 6.1.7
  • 设计落地：AI coding 落地清单与页面骨架模板
  • 样式 token：采用行业标准命名（--color-* / --text-* / --space-*）
